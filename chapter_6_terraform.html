1. Terraform이 중요한 이유

Terraform은 인프라를 코드로 정의하고 자동 생성하는 IaC 도구이다. 기능경기대회에서는 AWS Console을 클릭해서 구성하는 것보다 Terraform으로 빠르고 정확하게 반복 배포하는 능력이 중요하다.

재현성같은 코드를 실행하면 같은 인프라를 다시 만들 수 있음
속도VPC, ECS, EKS, RDS를 한 번에 생성 가능
검증plan을 통해 변경 사항을 사전에 확인 가능
버전관리Git으로 코드 변경 이력을 관리 가능
기능경기 실전에서는 “빠르게 만들기”보다 “재실행해도 깨지지 않는 코드”를 작성하는 것이 중요하다.

2. 기본 파일 구조

규모가 작은 문제는 하나의 main.tf로도 가능하지만, 실전에서는 리소스별로 파일을 나누는 것이 안전하다.

terraform/ ├─ provider.tf ├─ variables.tf ├─ terraform.tfvars ├─ network.tf ├─ security.tf ├─ iam.tf ├─ ecs.tf ├─ eks.tf ├─ database.tf └─ outputs.tf
파일역할
provider.tfAWS Provider와 Region 설정
variables.tf입력 변수 선언
terraform.tfvars변수 실제 값 지정
outputs.tfALB DNS, VPC ID 등 결과 출력
network.tfVPC, Subnet, Route Table, NAT 구성

3. Terraform 실행 흐름

terraform init
terraform fmt
terraform validate
terraform plan
terraform apply
terraform destroy
명령어설명
initProvider와 Module 초기화
fmt코드 형식 정리
validate문법 검증
plan생성/수정/삭제 미리보기
apply실제 인프라 반영
destroy생성한 리소스 삭제
plan 없이 바로 apply하면 잘못된 삭제나 비용 발생 리소스 생성을 놓칠 수 있다.

4. Provider와 변수

provider.tf

terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = var.region
}

variables.tf

variable "region" {
  type    = string
  default = "ap-northeast-2"
}

variable "project_name" {
  type    = string
  default = "skills"
}

variable "vpc_cidr" {
  type    = string
  default = "10.0.0.0/16"
}

terraform.tfvars

region       = "ap-northeast-2"
project_name = "skills"
vpc_cidr     = "10.0.0.0/16"

5. VPC Terraform 기본 패턴

resource "aws_vpc" "main" {
  cidr_block           = var.vpc_cidr
  enable_dns_support   = true
  enable_dns_hostnames = true

  tags = {
    Name = "${var.project_name}-vpc"
  }
}

resource "aws_subnet" "public_a" {
  vpc_id                  = aws_vpc.main.id
  cidr_block              = "10.0.1.0/24"
  availability_zone       = "ap-northeast-2a"
  map_public_ip_on_launch = true

  tags = {
    Name = "${var.project_name}-public-a"
  }
}

resource "aws_subnet" "private_a" {
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.11.0/24"
  availability_zone = "ap-northeast-2a"

  tags = {
    Name = "${var.project_name}-private-a"
  }
}
EKS와 ECS에서는 enable_dns_support, enable_dns_hostnames를 true로 설정하는 것이 좋다.

6. Route Table과 NAT Gateway

resource "aws_internet_gateway" "main" {
  vpc_id = aws_vpc.main.id
}

resource "aws_route_table" "public" {
  vpc_id = aws_vpc.main.id
}

resource "aws_route" "public_default" {
  route_table_id         = aws_route_table.public.id
  destination_cidr_block = "0.0.0.0/0"
  gateway_id             = aws_internet_gateway.main.id
}

resource "aws_eip" "nat" {
  domain = "vpc"
}

resource "aws_nat_gateway" "main" {
  allocation_id = aws_eip.nat.id
  subnet_id     = aws_subnet.public_a.id
}

resource "aws_route" "private_default" {
  route_table_id         = aws_route_table.private.id
  destination_cidr_block = "0.0.0.0/0"
  nat_gateway_id         = aws_nat_gateway.main.id
}
NAT Gateway는 Public Subnet에 있어야 하며, Private Route Table이 NAT Gateway를 향해야 한다.

7. Security Group 패턴

실전에서는 Source CIDR보다 Security Group 참조 방식이 안전하다.

resource "aws_security_group" "alb" {
  name   = "skills-alb-sg"
  vpc_id = aws_vpc.main.id

  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "aws_security_group" "app" {
  name   = "skills-app-sg"
  vpc_id = aws_vpc.main.id

  ingress {
    from_port       = 8080
    to_port         = 8080
    protocol        = "tcp"
    security_groups = [aws_security_group.alb.id]
  }
}

8. ECS Terraform 핵심

resource "aws_ecs_cluster" "main" {
  name = "${var.project_name}-cluster"
}

resource "aws_cloudwatch_log_group" "app" {
  name              = "/ecs/${var.project_name}-app"
  retention_in_days = 7
}

resource "aws_ecs_service" "app" {
  name            = "${var.project_name}-service"
  cluster         = aws_ecs_cluster.main.id
  task_definition = aws_ecs_task_definition.app.arn
  desired_count   = 2
  launch_type     = "FARGATE"

  network_configuration {
    subnets         = [aws_subnet.private_a.id, aws_subnet.private_b.id]
    security_groups = [aws_security_group.app.id]
  }

  load_balancer {
    target_group_arn = aws_lb_target_group.app.arn
    container_name   = "app"
    container_port   = 8080
  }
}
ECS Service와 Target Group 연결 시 container_name, container_port가 Task Definition과 일치해야 한다.

9. EKS Terraform 핵심

EKS는 IAM Role, VPC/Subnet, Node Group, Addon, aws-auth 구성이 중요하다. 실전에서는 Terraform 공식 모듈을 활용하면 속도를 높일 수 있다.

module "eks" {
  source  = "terraform-aws-modules/eks/aws"
  version = "~> 20.0"

  cluster_name    = "${var.project_name}-eks"
  cluster_version = "1.30"

  vpc_id     = aws_vpc.main.id
  subnet_ids = [aws_subnet.private_a.id, aws_subnet.private_b.id]

  eks_managed_node_groups = {
    default = {
      instance_types = ["t3.medium"]
      min_size       = 1
      max_size       = 3
      desired_size   = 2
    }
  }
}
EKS Node가 Join하지 못하면 IAM Role, Subnet Route, Security Group, aws-auth 설정을 확인한다.

12. 기능경기 풀이 순서

  1. Network: VPC, Subnet, IGW, NAT, Route Table, SG
  2. IAM: ECS/EKS/Lambda/RDS 접근 Role과 Policy
  3. Storage/DB: RDS, DynamoDB, S3
  4. Compute: ECS Service 또는 EKS Deployment
  5. Load Balancer: ALB, Target Group, Listener
  6. DNS: Route 53 Alias
  7. Monitoring: CloudWatch Logs, Alarm
  8. 검증: curl, kubectl, AWS CLI, CloudWatch Logs
가장 안전한 순서는 Network → IAM → DB → Compute → ALB → DNS → Monitoring이다.

13. 실전 체크리스트

  • terraform fmt를 실행했는가?
  • terraform validate가 성공했는가?
  • terraform plan 결과에서 삭제 리소스가 없는가?
  • VPC/Subnet CIDR이 겹치지 않는가?
  • Public/Private Route Table Association이 정확한가?
  • ECS/EKS IAM Role이 정확한가?
  • ALB DNS Output을 출력했는가?
  • 배포 후 실제 URL로 테스트했는가?

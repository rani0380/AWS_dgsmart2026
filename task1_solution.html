제1과제 배포 파일

과제에서 사용하는 Book App과 S3 정적 웹페이지 파일입니다. 버튼을 눌러 개별 다운로드한 뒤 과제 환경에 배포하세요.

① Book App 실행 파일

Linux AMD64 백엔드 애플리케이션

실행 파일 다운로드
② Frontend index.html

S3에 업로드할 정적 웹페이지

HTML 다운로드
③ main.jpeg

index.html에서 사용하는 헤더 배경

이미지 다운로드
프론트 화면 미리보기 배포 안내서 다운로드

Book App 실행

chmod +x book-linux-amd64
export AWS_REGION=ap-northeast-2
export TABLE_NAME=unicorn-concert-db
./book-linux-amd64

S3 정적 파일 업로드

ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
BUCKET=unicorn-web-$ACCOUNT_ID

aws s3 cp index.html s3://$BUCKET/index.html
aws s3 cp main.jpeg s3://$BUCKET/main.jpeg
실행 파일은 Linux AMD64용입니다. Windows에서 직접 실행하는 파일이 아니며, ECR 이미지 빌드 또는 Linux 환경에서 사용해야 합니다.

단계별 풀이

1. Networking 2.0점

unicorn-vpc를 10.97.0.0/16으로 만들고 3개 AZ에 Public/Private 서브넷을 각각 구성합니다.

구분abc
Public10.97.0.0/2410.97.1.0/2410.97.2.0/24
Private10.97.10.0/2410.97.11.0/2410.97.12.0/24
  • Public: unicorn-igw + 공용 unicorn-rt-pub
  • Private: AZ별 NAT Gateway와 unicorn-rt-priv-{a,b,c}
  • Endpoint: S3, ecr.api, ecr.dkr
  • VPC Flow Log 활성화
  • Private Subnet에 CloudShell VPC Environment unicorn-mark 구성
aws ec2 describe-vpcs --filters Name=tag:Name,Values=unicorn-vpc \
  --query "Vpcs[].CidrBlock" --output text

aws ec2 describe-subnets --filters Name=tag:Name,Values=unicorn-subnet-* \
  --query "Subnets[].[Tags[?Key=='Name']|[0].Value,CidrBlock]" --output table
2. KMS 1.0점

세 키 모두 90일 자동 교체를 설정합니다. 권한은 실제 사용하는 서비스와 역할에만 부여합니다.

Alias용도리전/유형
alias/unicorn-kms-appSecrets Manager, DynamoDBap-northeast-2
alias/unicorn-kms-dataS3, ECRap-northeast-2
alias/unicorn-kms-platformEKS Secrets·EBS·Logs·Lambdaus-east-1 다중 리전 키 요구사항 확인
for a in app data platform; do
  aws kms get-key-rotation-status \
    --key-id alias/unicorn-kms-$a \
    --query "[KeyRotationEnabled,RotationPeriodInDays]" --output text
done
3. S3·DynamoDB·ECR 3.0점
S3unicorn-web-<ACCOUNT_ID>
Public 차단, Versioning, Data CMK
DynamoDBunicorn-concert-db
PAY_PER_REQUEST, PITR, 삭제 방지, App CMK
ECRunicorn-concert-app
Data CMK, Scan on push, Tag immutability 설정

DynamoDB PK는 booking_id, GSI는 client-id-created-at-index이며 client_id를 PK, created_at을 SK로 지정합니다. ECR에는 v1.0.0과 latest 이미지를 올리고 스캔 결과를 확인합니다.

aws ecr describe-image-scan-findings \
  --repository-name unicorn-concert-app --image-id imageTag=v1.0.0

aws dynamodb describe-continuous-backups \
  --table-name unicorn-concert-db
4. EKS와 애플리케이션 4.5점
  • Cluster: unicorn-eks-cluster / 1.35 / Private Endpoint / 모든 Control Plane Log
  • App NodeGroup: label unicorn=app, 2대 이상, Private Subnet, Name 태그 unicorn-k8snode-app-node
  • Addon NodeGroup: label unicorn=addon, 1대 이상, Name 태그 unicorn-k8snode-addon-node
  • Namespace: unicorn / Deployment: unicorn-book-app-deploy / Service: unicorn-book-app-svc
  • container name: book / port: 8080 / AWS_REGION·TABLE_NAME 환경변수
  • /health 기반 Liveness·Readiness Probe, preStop, terminationGracePeriodSeconds
  • Pod Identity Role은 현재 클러스터로 제한하고 DynamoDB 최소권한만 부여
kubectl get nodes -L unicorn
kubectl -n unicorn get deploy,po,svc -o wide
kubectl -n unicorn describe deploy unicorn-book-app-deploy
kubectl -n unicorn get po -o jsonpath='{range .items[*]}{.metadata.name}{"  "}{.spec.nodeSelector}{"\n"}{end}'
Addon은 Addon NodeGroup, Book App과 DaemonSet은 요구된 노드에 배치되는지 반드시 실제 Pod 위치로 확인합니다.
5. Lambda·ALB·CloudFront·WAF 6.5점

unicorn-get-booking-func는 booking_id 필수, email·concert_name 선택 조건으로 DynamoDB를 조회하고 JSON을 반환합니다. Platform CMK와 /unicorn/lambda/get-booking 로그 그룹을 사용합니다.

요청라우팅 대상
GET /v1/bookLambda Target Group
POST /v1/bookEKS Book App Target Group
GET /healthEKS Book App Target Group
  • unicorn-alb는 Internal, HTTP 80
  • CloudFront는 S3 OAC Origin + ALB VPC Origin
  • CloudFront Comment: unicorn-svc-cf
  • 직접 ALB 요청은 거절하고 CloudFront 경유 요청만 허용
  • us-east-1 WAF unicorn-waf를 CloudFront에 연결
  • CommonRuleSet + KnownBadInputsRuleSet + 60초 50건 Rate Rule
  • 차단 응답: HTTP 403 / Request blocked by Unicorn WAF
# CloudFront를 통한 정상 확인
curl -i https://<CLOUDFRONT_DOMAIN>/health

# XSS 차단 확인
curl -i "https://<CLOUDFRONT_DOMAIN>/?q=%3Cscript%3Ealert(1)%3C/script%3E"
6. Security·Observability·Grafana 4.5점

Audit Role은 unicorn-audit-role, External ID는 unicorn-audit-2026<선수등번호>, 최대 세션은 1시간입니다. DynamoDB 조회와 VPC·EKS Describe만 Inline Policy로 허용합니다.

  • Fluent Bit DaemonSet으로 로그를 10초 이내 CloudWatch 전송
  • /health 로그 제외, Log Group /unicorn/eks/book-app
  • Prometheus·Grafana는 monitoring Namespace
  • Grafana ALB: unicorn-grafana-alb / TG: unicorn-grafana-tg
  • Dashboard: unicorn-grafana-dashboard
  • Node CPU·Memory, Pod 상태, Ready Pod 수, HTTP 응답시간 패널
aws logs tail /unicorn/eks/book-app --since 5m
kubectl -n monitoring get po,svc,ingress
kubectl -n monitoring get po -o wide
7. DynamoDB Stream 추가과제 6.0점

source-db에 데이터가 들어오면 Stream으로 컨테이너 이미지 기반 Lambda ticket-processor를 호출합니다. price × amount 값을 total_price로 추가해 destination-db에 60초 안에 저장합니다.

  • 두 테이블 PK: ticket_id
  • source-db: Stream 활성화 + created_at 기반 TTL 300초
  • Lambda: 컨테이너 형식 + Provisioned Concurrency로 콜드스타트 방지
  • Event Source Mapping의 시작 위치와 Batch 실패를 점검
aws dynamodb put-item --table-name source-db --item '{
  "ticket_id":{"S":"abcd1111"},
  "price":{"N":"1000"},
  "amount":{"N":"3"},
  "created_at":{"N":"<EPOCH_NOW_PLUS_300>"}
}'

aws dynamodb get-item --table-name destination-db \
  --key '{"ticket_id":{"S":"abcd1111"}}'

예상 total_price: 3000. TTL 속성에는 현재 시각이 아니라 만료될 epoch time을 넣습니다.

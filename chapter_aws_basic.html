CH 1

AWS 개요 / 클라우드 개념

▼

클라우드란?

인터넷을 통해 서버, 스토리지, 데이터베이스, 네트워크 등 IT 자원을 필요할 때 빌려 쓰는 방식입니다. 서버를 직접 사지 않아도 됩니다.

IaaS

Infrastructure as a Service

서버·네트워크·스토리지만 빌린다. OS/앱은 직접 설치.
예: EC2, VPC, S3

PaaS

Platform as a Service

런타임 환경까지 제공. 앱 코드만 올리면 된다.
예: Elastic Beanstalk, Lambda

SaaS

Software as a Service

완성된 소프트웨어를 구독. 설치 없이 웹브라우저로 사용.
예: Gmail, Office 365

AWS 글로벌 인프라

용어설명경기 관련 값
리전 (Region)지리적으로 분리된 데이터센터 묶음ap-northeast-2 (서울)
가용 영역 (AZ)리전 안에서 물리적으로 격리된 데이터센터ap-northeast-2a / 2c
엣지 로케이션CDN 캐싱 서버 (CloudFront)전 세계 400+ 곳
⭐ 경기 핵심
모든 리소스는 ap-northeast-2 (서울 리전)에 생성합니다. CLI 명령 시 --region ap-northeast-2 또는 환경변수 AWS_DEFAULT_REGION=ap-northeast-2를 설정하세요.

AWS 콘솔 vs CLI

콘솔

웹 GUI

브라우저에서 클릭으로 조작. 빠른 확인에 유리하지만 반복 작업에 불편.

CLI

명령어 인터페이스

터미널에서 명령어로 조작. 스크립트 자동화 가능. 경기 채점은 CLI 결과 기준.

# AWS CLI 기본 명령 구조 aws <서비스> <동작> [옵션] # 예: S3 버킷 목록 확인 aws s3 ls # 현재 계정 확인 aws sts get-caller-identity

CH 2

IAM — 계정과 권한

▼

IAM이란?

AWS 리소스에 누가, 무엇을, 어디서 할 수 있는지를 정의하는 서비스입니다. "열쇠와 자물쇠 관리자"로 생각하세요.

사용자 (User)

IAM User

실제 사람 또는 애플리케이션 계정. 액세스 키(Access Key + Secret Key)로 인증.

그룹 (Group)

IAM Group

여러 사용자를 묶어 동일한 권한을 한번에 부여. 예: Developers 그룹.

역할 (Role)

IAM Role

EC2, Lambda 등 AWS 서비스가 다른 서비스를 호출할 때 사용. 액세스 키 불필요.

정책 (Policy)

IAM Policy

허용/거부 규칙을 JSON으로 작성. User/Group/Role에 연결해서 권한 부여.

IAM Policy 구조

{ "Version": "2012-10-17", "Statement": [ { "Effect": "Allow", // Allow 또는 Deny "Action": "s3:GetObject", // 허용할 작업 "Resource": "arn:aws:s3:::my-bucket/*" // 대상 리소스 } ] }
⚠ 경기 주의사항
경기 환경에서는 IAM 액세스 키를 직접 생성하지 않습니다. EC2/ECS에는 IAM Role을 인스턴스 프로파일로 연결하여 권한을 부여합니다. 코드에 키를 하드코딩하면 감점됩니다.

주요 CLI 명령

# 현재 자격증명 확인 aws sts get-caller-identity # IAM Role 목록 조회 aws iam list-roles --query "Roles[].RoleName" --output table # Role에 연결된 정책 확인 aws iam list-attached-role-policies --role-name MyRole # EC2 인스턴스 프로파일 연결 확인 aws ec2 describe-iam-instance-profile-associations

최소 권한 원칙 (Least Privilege)

  • 필요한 권한만 부여, 절대 AdministratorAccess를 무분별하게 사용하지 않는다
  • ECS Task에는 필요한 서비스만 접근 가능한 Task Role을 생성한다
  • DynamoDB 접근 Role에는 dynamodb:PutItem, GetItem, Query 등 필요한 것만 허용
  • CloudWatch Logs 접근에는 logs:CreateLogGroup, logs:PutLogEvents만 부여
💡 확인 문제

EC2 인스턴스가 S3에서 파일을 읽게 하려면 무엇을 사용해야 하나요? ①액세스 키 ②IAM Role

② IAM Role — 인스턴스 프로파일로 EC2에 Role을 연결합니다. 액세스 키는 코드에 하드코딩하면 보안 위험이 있고, 경기에서도 감점 대상입니다.
CH 3

EC2 — 가상 서버

▼

EC2란?

AWS에서 제공하는 가상 서버(Virtual Machine)입니다. CPU, 메모리, 스토리지를 선택해 몇 분 안에 서버를 시작할 수 있습니다.

핵심 구성요소

구성요소설명경기 기본값
AMI인스턴스 시작 이미지 (OS + 기본 소프트웨어)Amazon Linux 2023
인스턴스 타입CPU/메모리 사양 (t3.micro, m5.large 등)t3.micro (프리티어)
키 페어SSH 접속에 사용하는 공개키/개인키 쌍.pem 파일 생성 후 보관
보안 그룹인스턴스의 방화벽. 인바운드/아웃바운드 규칙SSH(22), HTTP(80), 앱포트
사용자 데이터인스턴스 최초 시작 시 자동 실행할 스크립트패키지 설치, 서비스 시작

보안 그룹 규칙 예시

# 보안 그룹 생성 aws ec2 create-security-group \ --group-name web-sg \ --description "Web server SG" \ --vpc-id vpc-xxxxxxxx # HTTP(80) 허용 aws ec2 authorize-security-group-ingress \ --group-id sg-xxxxxxxx \ --protocol tcp --port 80 --cidr 0.0.0.0/0 # SSH(22) 허용 aws ec2 authorize-security-group-ingress \ --group-id sg-xxxxxxxx \ --protocol tcp --port 22 --cidr 0.0.0.0/0

사용자 데이터 (User Data) 예시

#!/bin/bash # EC2 시작 시 자동 실행됩니다 yum update -y yum install -y docker systemctl start docker systemctl enable docker usermod -aG docker ec2-user

주요 CLI 명령

# 실행 중인 인스턴스 목록 aws ec2 describe-instances \ --filters "Name=instance-state-name,Values=running" \ --query "Reservations[].Instances[].[InstanceId,PublicIpAddress,Tags[?Key=='Name'].Value|[0]]" \ --output table # 인스턴스 퍼블릭 IP 확인 aws ec2 describe-instances \ --instance-ids i-xxxxxxxx \ --query "Reservations[0].Instances[0].PublicIpAddress" \ --output text # SSH 접속 ssh -i my-key.pem ec2-user@<퍼블릭IP>
⭐ 경기 핵심
ECS Fargate 과제에서는 EC2를 직접 사용하지 않지만, EFS 마운트나 Bastion 접속 등에서 EC2가 등장합니다. 보안 그룹 체이닝을 꼭 이해하세요: ALB SG → ECS SG → RDS SG 순으로 Source를 SG ID로 지정합니다.
💡 확인 문제

EC2 인스턴스가 시작될 때 자동으로 소프트웨어를 설치하려면 어디에 스크립트를 작성하나요?

사용자 데이터(User Data) — 인스턴스 생성 시 제공하는 bash 스크립트로, 최초 부팅 때 한 번 자동 실행됩니다.
CH 4

S3 — 스토리지

▼

S3란?

Simple Storage Service — 파일(객체)을 버킷에 저장하는 서비스입니다. 용량 제한 없이 어떤 데이터든 저장 가능합니다.

버킷 (Bucket)

파일 보관함

전 세계에서 유일한 이름을 가져야 합니다. 리전별로 생성됩니다.

객체 (Object)

저장된 파일

Key(파일경로)와 Value(파일내용)로 구성. 최대 5TB 파일 저장 가능.

정적 웹 호스팅

HTML 파일 서빙

S3 버킷을 웹서버처럼 사용. index.html을 공개해 정적 사이트 운영.

경기 자주 출제: 정적 웹사이트 호스팅

브라우저 → CloudFront → S3 버킷 (정적 파일) ↓ ALB → ECS (API 서버)
# 버킷 생성 (서울 리전) aws s3 mb s3://my-bucket-name --region ap-northeast-2 # 파일 업로드 aws s3 cp index.html s3://my-bucket-name/ aws s3 cp main.jpeg s3://my-bucket-name/ # 정적 웹 호스팅 활성화 aws s3 website s3://my-bucket-name \ --index-document index.html \ --error-document error.html # 퍼블릭 액세스 차단 해제 (CloudFront OAC 사용 시 불필요) aws s3api put-public-access-block \ --bucket my-bucket-name \ --public-access-block-configuration "BlockPublicAcls=false,..." # 버킷 내용 확인 aws s3 ls s3://my-bucket-name/
⭐ 경기 핵심
제1과제에서 S3 + CloudFront 구성이 필수입니다. CloudFront OAC(Origin Access Control)을 사용해 S3를 CloudFront를 통해서만 접근 가능하게 설정하세요. S3 직접 접근은 차단하고 CloudFront URL로만 서빙합니다.

버킷 태그 설정 (채점 항목)

# 버킷에 태그 추가 (채점 기준 확인 필수) aws s3api put-bucket-tagging \ --bucket my-bucket-name \ --tagging 'TagSet=[{Key=Module,Value=CloudFront}]' # 태그 확인 aws s3api get-bucket-tagging --bucket my-bucket-name
💡 확인 문제

S3 버킷을 외부에 직접 노출하지 않고 CloudFront를 통해서만 접근하게 하는 기능은?

OAC (Origin Access Control) — CloudFront Distribution에 OAC를 설정하고, S3 버킷 정책에 CloudFront Principal만 허용하면 됩니다.
CH 5

VPC — 네트워크

▼

VPC란?

Virtual Private Cloud — AWS 안에 나만의 가상 네트워크 공간입니다. 인터넷과 격리된 사설망에서 리소스를 배치합니다.

VPC 구성요소

구성요소설명경기 기본값
VPC CIDR전체 네트워크 주소 범위10.0.0.0/16
퍼블릭 서브넷인터넷 게이트웨이와 연결된 서브넷. ALB, NAT GW 배치10.0.1.0/24, 10.0.2.0/24
프라이빗 서브넷인터넷 직접 노출 없는 서브넷. ECS, RDS 배치10.0.11.0/24, 10.0.12.0/24
인터넷 게이트웨이VPC와 인터넷을 연결VPC당 1개
NAT 게이트웨이프라이빗 서브넷에서 인터넷 아웃바운드 허용퍼블릭 서브넷에 배치
라우팅 테이블서브넷의 트래픽 경로 설정0.0.0.0/0 → IGW (퍼블릭)

전형적인 경기 아키텍처

인터넷 │ ▼ [인터넷 게이트웨이] │ ▼ [퍼블릭 서브넷 2a / 2c] ├── ALB (포트 80/443) └── NAT 게이트웨이 │ ▼ [프라이빗 서브넷 2a / 2c] ├── ECS Fargate (포트 8080) └── RDS / Aurora

VPC 생성 CLI

# 1. VPC 생성 VPC_ID=$(aws ec2 create-vpc \ --cidr-block 10.0.0.0/16 \ --query "Vpc.VpcId" --output text) # 2. 서브넷 생성 (퍼블릭, ap-northeast-2a) aws ec2 create-subnet \ --vpc-id $VPC_ID \ --cidr-block 10.0.1.0/24 \ --availability-zone ap-northeast-2a # 3. 인터넷 게이트웨이 연결 IGW_ID=$(aws ec2 create-internet-gateway \ --query "InternetGateway.InternetGatewayId" --output text) aws ec2 attach-internet-gateway \ --internet-gateway-id $IGW_ID --vpc-id $VPC_ID # 4. 라우팅 테이블에 IGW 경로 추가 aws ec2 create-route \ --route-table-id rtb-xxxxxxxx \ --destination-cidr-block 0.0.0.0/0 \ --gateway-id $IGW_ID
⭐ 경기 핵심
서브넷은 반드시 다른 AZ(ap-northeast-2a, ap-northeast-2c)에 2개 이상 만드세요. ALB는 2개 이상의 AZ에 서브넷이 있어야 생성됩니다. 채점 항목에 "서로 다른 AZ 확인"이 자주 등장합니다.
💡 확인 문제

ECS 컨테이너가 외부 인터넷(예: DockerHub)에 접근하려면 프라이빗 서브넷에 무엇이 필요한가요?

NAT 게이트웨이 — 퍼블릭 서브넷에 NAT GW를 만들고, 프라이빗 서브넷 라우팅 테이블의 0.0.0.0/0을 NAT GW로 지정합니다.
CH 6

RDS / DynamoDB — 데이터베이스

▼

RDS vs DynamoDB

항목RDS (관계형)DynamoDB (NoSQL)
데이터 구조테이블, 행, 열 (스키마 고정)Key-Value, 스키마 자유
조회 방법SQL (SELECT, JOIN 등)PK/SK 기반, GSI
확장성수직 확장 (인스턴스 업그레이드)자동 수평 확장
경기 사용MySQL, PostgreSQL, Aurora과제 데이터 저장소
접속 방식엔드포인트:포트 + ID/PWAWS SDK / CLI

DynamoDB — 경기 필수

# 테이블 생성 aws dynamodb create-table \ --table-name Books \ --attribute-definitions AttributeName=id,AttributeType=S \ --key-schema AttributeName=id,KeyType=HASH \ --billing-mode PAY_PER_REQUEST \ --region ap-northeast-2 # 테이블 상태 확인 aws dynamodb describe-table \ --table-name Books \ --query "Table.TableStatus" # 데이터 저장 (PutItem) aws dynamodb put-item \ --table-name Books \ --item '{"id":{"S":"001"},"title":{"S":"AWS 기초"},"author":{"S":"홍길동"}}' # 데이터 조회 (GetItem) aws dynamodb get-item \ --table-name Books \ --key '{"id":{"S":"001"}}' # 전체 스캔 aws dynamodb scan --table-name Books

RDS — MySQL 예시

# RDS MySQL 인스턴스 생성 aws rds create-db-instance \ --db-instance-identifier my-mysql \ --db-instance-class db.t3.micro \ --engine mysql \ --master-username admin \ --master-user-password MyPass1234! \ --allocated-storage 20 \ --db-subnet-group-name my-subnet-group \ --vpc-security-group-ids sg-xxxxxxxx \ --no-publicly-accessible # RDS 상태 확인 aws rds describe-db-instances \ --db-instance-identifier my-mysql \ --query "DBInstances[0].DBInstanceStatus" # 엔드포인트 확인 aws rds describe-db-instances \ --db-instance-identifier my-mysql \ --query "DBInstances[0].Endpoint.Address"
⭐ 경기 핵심
제1과제에서 DynamoDB는 ECS 앱의 데이터 저장소로 사용됩니다. 테이블 이름과 파티션 키를 환경변수(TABLE_NAME)로 ECS Task에 전달합니다. 앱이 DynamoDB에 PutItem할 수 있도록 Task Role에 dynamodb 권한을 추가하세요.
⚠ DynamoDB 과금 주의
테이블 생성 시 --billing-mode PAY_PER_REQUEST를 사용하면 요청 수 기반 과금이라 경기 환경에 적합합니다. 기본값인 PROVISIONED는 용량을 직접 지정해야 합니다.
💡 확인 문제

ECS Fargate 컨테이너 앱이 DynamoDB에 데이터를 저장할 때 필요한 것 두 가지는?

① IAM Task Role (dynamodb:PutItem 권한 포함) — 컨테이너가 DynamoDB를 호출하는 권한 ② 환경변수 TABLE_NAME — 코드가 어느 테이블에 저장할지 알아야 하므로 Task Definition에 설정

📋 서비스 연결 관계 총정리

인터넷 │ ▼ CloudFront ──────────────────── S3 (정적 파일: index.html, main.jpeg) │ ▼ ALB (80/443, 퍼블릭 서브넷) │ alb-sg → ecs-sg (Source: alb-sg) ▼ ECS Fargate (포트 8080, 프라이빗 서브넷) │ Task Role: DynamoDB + CloudWatch Logs 권한 │ 환경변수: AWS_REGION, TABLE_NAME ├──→ DynamoDB (Books 테이블, ap-northeast-2) └──→ CloudWatch Logs (/skillskorea/ecs/app)
